The five things that matter most

  1. Rotate credentials today. Demo logins for real production accounts (including a five-building strata manager) are in tracked files: BUSINESS_MARKETPLACE_GUIDE.html, supabase/seed_business.sql, supabase/seed_strata.sql, and a phase plan. .gitignore:27-30 says the repo is public. Anyone can log in as a manager and read residents' incident evidence and ESA medical letters. (S-H1)
  2. The product has no URLs. /app is one client page with a 26-way ternary on useState. No deep links, Back exits the app, refresh loses your place, every screen ships in one bundle. (A-1)
  3. Nothing is enforced. No CI, pnpm lint has never worked (no eslint dependency or config), zero tests on anything touching Supabase, HTTP or React. Quality today is one person running pnpm build by hand. (P-1)
  4. A real product bug hides in the domain layer: pets registered through the app stay draft forever — nothing writes registration_status='pending', and the approvals queue reads only pending. Managers never see app-registered pets. (D-1)
  5. The database is worth keeping. All 55 tables have RLS, mutations run through SECURITY DEFINER RPCs with single-use tokens and BEFORE triggers that even admins cannot bypass, bucket paths are grammar-pinned. The rebuild should happen around this schema, not instead of it.

Recommendation: Do not rewrite. The weighted rating is 4.2/10 (C−) today and reaches 8.1/10 (A−) on the roadmap in §16 without a single line of the schema being thrown away. Freeze feature work for one quarter; spend weeks 1–3 on hygiene and security (no product change visible), weeks 4–15 on the structural migration described in §15, feature by feature, behind the existing schema. The schema and its tests are the asset; the React layer is the liability.

The screen switcher, and why it is the central structural problem

app/app/page.tsx:120-134 holds activeTab, currentScreen, selectedPetId, selectedBusinessId, careKind, carePetId, selectedCaseId in React state. handleNavigate(screen, id?, petId?) (L197-212) is polymorphic — id means a business, a care kind, a violation or a pet depending on screen. A 240-line registry (lib/navigation.ts:128-154, ID_BEARING, ID_REQUIRED) exists purely to police that ambiguity, and its comments document the bugs it was written to stop.

  • No deep links: a notification's action_target is a string like my-cases:<id>, not a URL.
  • Browser Back leaves the product; refresh always lands on home/dashboard (effect L137-141).
  • All 27 screens are statically imported (L8-33) → one client bundle for everything the resident and manager can ever see.
  • Adding a screen means editing the ternary chain, CONTENT_MAX, SCREEN_SURFACES, ID_BEARING, ios-tab-bar.tsx and app-sidebar.tsx (which declare different tab lists: the tab bar has an AI centre slot, the sidebar has alerts).
  • /strata-portal, /businessaccess and /admin repeat the pattern with their own tab state, their own sidebar and their own login form — five hand-built email/password forms in total.

04 · Security

4.5/10 · C−Security (composite) — Database controls are exemplary; the application layer around them has had almost no hardening, and credentials are in the repo.

The database layer is strong — RLS on all 55 tables, scoped helper predicates, reviewed SECURITY DEFINER functions, grant hygiene, grammar-pinned storage paths. The application layer has not received the same treatment: no rate limiting, no security headers, a public account-creation door that bypasses the OTP gate, an open redirect, HTML injection into outbound email, and production credentials in tracked files.

10 · Design system proposal

2.5/10 · D−Design-system maturity today — Tokens exist and are good; nothing above them does, so the system cannot be applied, tested or governed. This section is the proposal to fix that.

Keep the existing token philosophy — it is the best-argued part of the front end — and build the missing middle: a small set of pattern components that every screen must use, a type scale, and a shell.

Token architecture (extend, don't replace)

Colour

  • Keep grounds, brand, teal accent, semantic set. Add --primary-strong (≈#C8651B) for text on white — #FD9340 is 3.5:1 and fails AA for body text; the colour doc already knows this.
  • Promote --warning-strong pattern to every semantic: -soft (tint), -strong (text), base (fill).
  • Status colour is not accent colour: booking/violation/registration states map to the semantic set through one statusTone(enum) function, not per-screen maps.

Type scale (replace 17 arbitrary sizes)

  • caption 11/14 · meta 12/16 · body-sm 13/18 · body 15/22 · title 17/24 600 · heading 22/28 700 · display 28/34 700.
  • Expose as Tailwind utilities (text-caption …) via @theme; lint-ban text-[…px].
  • Tabular numerals for money, counts, countdowns.

Space, radius, elevation, motion

  • Spacing on a 4px grid with named stops 1–10; page gutter 16 mobile / 24 desktop; card padding 16.
  • Radius: sm 8, md 14 (current), lg 20, full. Sheets use lg top corners.
  • Elevation: keep the two stops; add overlay for scrims (--scrim, theme-aware) and one z-index scale: base 0, sticky 30, overlay 50, toast 60.
  • Motion: one duration pair (120ms/200ms), one easing; respect prefers-reduced-motion.

Layout tokens

  • --nav-h, --tabbar-h, --safe-top/bottom so sticky sub-headers stop hard-coding 64px/44px.
  • Content widths: narrow 640, reading 720, console 1120.
  • Breakpoints used deliberately: md = sidebar appears; lg = two-column consoles.

13 · What is done right

An acquirer who only reads the findings will undervalue this. The following are unusual for a two-month, one-person codebase and should be protected through any restructuring.

Database as the enforcement point

Every table has RLS. State changes that matter (ladder, fine schedule, rule publishing, accommodation status, post attribution) go through SECURITY DEFINER RPCs that re-check scope, mint a transaction-local token, and are backed by BEFORE triggers that refuse direct writes — including from admins. Grant hygiene was measured on production and fixed.

"Positive grammar" everywhere

Storage paths, evidence arrays, community columns, money input, building codes: the code states what is allowed rather than denying what is not. community_posts_guard is a column registry. parseAmountToCents is a regex grammar with no float math.

Pure rule modules that mirror SQL and are test-pinned

violations.ts, disputes.ts, accommodations.ts, fine-schedule.ts, building-rules.ts, purge classifiers — enums derived from generated types so drift is a compile error; 383 tests in 0.6 s.

Signup and evidence design

OTP before account creation, hashed + peppered, timing-safe, enumeration-safe. Guest evidence uploaded to a bucket nobody can write directly, claimed by the intake RPC, purged if unclaimed. Accommodation documents: server-composed paths, resident supplies bytes only.

AI safety posture

Deterministic red flags before any model; classifier may only escalate; consent gate; retention; rendering through a whitelist parser; model IDs in env with measured rationale.

Honest engineering record

Commit bodies, the deferred-controls register and phase-0 findings distinguish deliberate gaps from neglect, with measurements. Zero TODOs and zero any is not an accident. The token file argues every colour choice.

Layering rules (enforce with eslint-plugin-boundaries)

  1. Routing is the URL. Every screen is a page; every notification target is a path.
  2. Reads are server-first. Pages read through queries.server.ts (server Supabase client, RLS still applies) and stream. Interactive lists use TanStack Query hydrated from the server payload. No module-level caches.
  3. Writes are server actions or route handlers with zod schemas, one requireUser()/requireCronSecret(), errors mapped to generic messages.
  4. One session provider, seeded from the server; middleware and client consume the same my_personas result.
  5. No barrel that mixes client and server. features/*/index.ts exports types and pure rules only.
  6. Generated types are the only DB types. View-models live per feature and are derived, never hand-declared enums.
  7. Every state machine has a SQL transition table (the violation pattern), and a TS mirror pinned by tests.
  8. Env validated at boot (shared/lib/env.ts, zod); no mock mode.
  9. UI composes patterns; screens contain no fixed inset-0, no Loader2, no text-[…px].
