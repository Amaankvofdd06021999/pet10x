# UI System and Notification Swipe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** One palette and one set of UI pieces across every screen (no brown, no teal, no raw colours), plus swipe-to-snooze/delete on notifications.

**Architecture:** Task 1 adds the new tokens and pieces and turns the old token names into temporary aliases of the new ones, so the brown disappears app-wide on day one without breaking any class. Batches then move screens onto the pieces and new token names. The last task deletes the aliases and the old component set and turns on a lint rule. Notifications get a migration (snooze/dismiss columns + three RPCs) and a `SwipeRow` piece.

**Tech Stack:** Next.js 16, React 19, Tailwind 4 (`@theme inline` in `app/globals.css`), Radix, sonner, Supabase, vitest (Node), pnpm 9.15.9.

**Spec:** `docs/superpowers/specs/2026-10-15-ui-system-design.md`

## Global Constraints

- pnpm is not on PATH: prefix commands with `PATH="$HOME/.corepack-bin:$PATH"`. Do not upgrade pnpm.
- Green gate for every task: `pnpm test`, `npx tsc --noEmit -p .`, `pnpm lint` (0 errors), `pnpm build`.
- Palette, piece variants, type sizes and copy exactly as the spec's §1–§4. No new colours.
- Text is never orange: all text is `text-foreground` or `text-muted-foreground` (white only on primary/danger fills).
- Behaviour, layout and flows do not change except the notification actions. A batch changes how things look, not what they do. Keep every `onClick`, `disabled`, `aria-*`, and test id.
- Unstyled `<button>` used as a tappable row may stay; anything styled as a button becomes `Button`.
- Validate with a positive grammar. SQL permission checks NULL-safe. Never `supabase db push`; the one migration is `supabase/migrations/20261018000001_ui_system.sql`; checks in `supabase/tests/part-j.sql`; `supabase/bundles/build.sh` cutoff `20261018`, checks list adds `part-j`, branch text `ui-system`.
- No raw database text to users (`dbErrorMessage`).
- One implementer at a time on this tree. Do not touch the live database outside the bundle flow.

## Review Focus

1. Focus visibility: an orange focus ring on an orange button is invisible — primary buttons need a ring offset (or a dark ring) so keyboard focus shows. (Task 1: style guide shows a focused primary button; reviewer checks the classes.)
2. Swipe vs scroll: a vertical scroll that starts on a row must scroll, not open the actions; a tap still opens the notification; only one row open at a time. (Task 2: pure `swipeIntent(dx, dy)` decision tested — horizontal only when |dx| > 10 and |dx| > 1.5·|dy|.)
3. Snooze times: "This evening (6 PM)" hidden from 17:00; "Tomorrow morning (8 AM)" correct across a DST change; times computed in `profiles.timezone`. (Task 2 tests on `snoozeOptions(now, tz)`.)
4. Aliases removed cleanly: after Task 7, no class anywhere references a removed token, an opacity tint, teal, or a hex literal (grep + the lint rule over the whole repo, landing page included).
5. Dark mode: every `-soft` token keeps dark-mode text readable (soft backgrounds in dark mode are dark tints, text light). (Task 1 defines them; style guide shows both modes.)

### Task 2: Notification snooze and delete

**Files:** create `supabase/migrations/20261018000001_ui_system.sql`, `supabase/tests/part-j.sql`, `components/ui/swipe-row.tsx`, `lib/notifications/snooze.ts` (+test), `lib/swipe.ts` (+test); modify `components/notifications/notification-row.tsx`, `components/screens/alerts-screen.tsx`, `components/notifications/console-inbox.tsx`, `lib/data/notification-store.ts` and the notifications reads in `lib/data/live.ts` (~1300–1440), the unread-count read, `app/api/notifications/dispatch/route.ts`, `lib/supabase/database.types.ts`, `supabase/bundles/build.sh`, bundles.

**Interfaces:**
- `snoozeOptions(now: Date, tz: string): Array<{ key: "hour" | "evening" | "morning"; label: string; until: Date }>` — labels exactly "In 1 hour", "This evening (6 PM)", "Tomorrow morning (8 AM)"; `evening` omitted when local time ≥ 17:00.
- `swipeIntent(dx: number, dy: number): "horizontal" | "vertical" | "undecided"`.
- `<SwipeRow actions={[{label, icon, onPress, tone}]} onOpenChange>` — one open at a time via a module-level "open row" signal.
- Data functions `snoozeNotification(id, until)`, `dismissNotification(id)`, `restoreNotification(id)` returning `{ error: string | null }`.

- [ ] Migration per spec §4: two columns; `snooze_notification`, `dismiss_notification`, `restore_notification` (definer, `search_path = public, pg_temp`, row must have `profile_id = auth.uid()` else `{ok:false,error:'forbidden'}`; snooze `p_until` must be `> now()` and `<= now() + interval '7 days'` else 22023; snooze clears `read_at`). Grant execute to authenticated only.
- [ ] part-j.sql: owner snooze/dismiss/restore work; stranger forbidden; past and 8-day snooze → 22023; a dismissed row and a sleeping row are excluded by the inbox filter expression.
- [ ] TDD `snoozeOptions` (10:00 → three options; 17:30 → two; a DST-change date in `America/Toronto` gives 08:00 local next day) and `swipeIntent` (dx 30 dy 5 → horizontal; dx 8 → undecided; dx 20 dy 25 → vertical).
- [ ] Every inbox read and the unread count add `dismissed_at is null` and `(snoozed_until is null or snoozed_until <= now())` (use `.is("dismissed_at", null).or("snoozed_until.is.null,snoozed_until.lte.<iso now>")`). The dispatcher's claim skips dismissed rows and rows still sleeping.
- [ ] `SwipeRow`: pointer events; reveal width 144px; snaps open past half; closes on outside tap or scroll; on hover/focus-within (desktop/keyboard) shows the same buttons inline. Buttons are real `Button`s with labels.
- [ ] `notification-row.tsx` wraps in `SwipeRow` with Snooze (opens a `Sheet` listing `snoozeOptions` in the person's timezone — `profiles.timezone` via the auth user, falling back to `Intl.DateTimeFormat().resolvedOptions().timeZone`) and Delete (optimistic hide, toast "Notification deleted" with action "Undo" for 5 s → `restoreNotification`). Errors toast the mapped sentence and restore the row.
- [ ] Regenerate bundles; gate; commit "Notifications can be snoozed or deleted with a swipe".
